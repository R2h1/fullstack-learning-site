21 · 长矛一：AI 模型层与推理优化（操练册） ​

达标目标：从「会调 API」打到「造得出推理核心」：手撕注意力 → 训一个 mini-GPT → LoRA 微调实证 → 用 vLLM 并压测 → 写 mini-vLLM 调度器。 一句话理由：2026 年只会 LangChain 串流程的候选人已经饱和，应用层往下走一层，是「AI 工程师」四个字重新值钱的分界线。 衔接：15 章（调用与 RAG 链路）、16 章（Agent）、23 章（评估给推理改动定指标）；mini-vLLM 的调度与显存管理与 22 章的内核工作同构，两把长矛互相喂。 ⚠️ 本章是操练册，不是教材：每节以「交付物」收口，代码骨架给出但要求你补完并过测试。

1. 为什么应用工程师要懂模型层 ​

  • 面试侧：追问三层之后（"RAG 延迟高怎么优化" → "首 token 为什么慢" → "KV Cache 为什么会爆"），背 API 文档的人到第三层就死，造过的人第三层开始才进入舒适区
  • 工程侧：推理成本 = 显存 × 时间，不懂 KV Cache / batching 就无法做真实的容量与成本决策（15 章成本模型只能算调用价，算不了自部署）
  • 定位侧：「懂模型的应用工程师」和「只会应用的应用工程师」简历上是两个职级

2. 路线（约 16–20 周，对应总计划阶段二前半） ​

2.1 手撕注意力（第 1–3 周） ​

  • 交付物：attention.py——单头/多头注意力、causal mask、KV Cache 版增量解码，每种实现配数值测试（与参考实现误差 < 1e-5）
  • 必须讲清的三件事：
    1. softmax(QKᵀ/√d)V 里每部分的形状与含义
    2. 为什么 causal mask 是 -inf 而不是删掉（并行训练与自回归解码的等价性）
    3. KV Cache 缓存的是 K/V 不是 Q，增量解码把 O(n²) 计算摊成每步 O(n)
  • 自检口述：白板画出一次 prefill 和 50 步 decode 的完整数据流

2.2 训练一个 mini-GPT（第 4–7 周） ​

  • 交付物：照 karpathy nanoGPT 路线（或 build-nanogpt）在小语料（如 Shakespeare/中文维基切片）上训出会说话的模型；记录 loss 曲线、采样样例、显存占用
  • 必须动手踩的三个坑：学习率 warmup、梯度裁剪、采样温度/top-p 对输出质量的影响各做一组对照实验
  • 自检口述：Transformer 一层里参数量都花在哪（注意力 vs FFN，大约 1:2）

2.3 LoRA 微调实证（第 8–11 周） ​

  • 交付物：选一个真实小任务（比如把「用户投诉工单」分成 6 类），基座用 Qwen 1.5B/3B 级别，QLoRA（4bit 基座 + LoRA）在单卡/租卡上完成微调，产出 eval 指标对比：zero-shot vs few-shot vs 微调后
  • 验收含成本账单：租卡单价 × 时长，对比同任务调 API 的成本，写清楚什么单量下微调才划算（这条是面试黄金答案）
  • 必会概念：LoRA 低秩旁路（只训 A·B 两个小矩阵）、r/alpha 怎么选、merge 与不 merge 的区别、什么任务不该微调（知识频繁更新 → RAG；行为/格式/领域语感 → 微调）

2.4 用 vLLM 并解释它（第 12–14 周） ​

  • 交付物：vLLM 部署你在 2.3 微调的模型，SSE 流式接通你的前端（复用 15/17 章），产出压测报告：不同并发下的 TTFT、TPOT、吞吐 tokens/s，与裸 HF transformers 推理对比
  • 必须讲清：PagedAttention（显存分页，解 KV Cache 碎片）、continuous batching（请求动态进出 batch，对位传统静态 batch 的队头阻塞）、prefill/decode 两阶段的资源画像差异（算力密集 vs 带宽密集）

2.5 写 mini-vLLM（第 15–20 周，本章的 D4 验收物） ​

  • 交付物：mini-vllm 仓库——单 GPU 简化版推理服务：请求队列 + continuous batching 调度器 + 分页 KV block 分配器 + 与 HuggingFace 模型的适配层；带测试与 README
  • 范围控制：不做量化、不做多卡并行，只攻调度与显存管理——这就是 vLLM 的护城河所在
  • 正确性测试：同 batch 内容在不同到达时序下输出一致；block 分配释放无泄漏（跑 10k 请求显存平稳）
  • 基准：与 vLLM 同参数对比吞吐，能解释差距在哪（并行策略、CUDA 内核、前缀缓存……）

必会：画 KV Cache 分页前后显存布局；讲 continuous batching 为什么能把吞吐提高数倍；给「微调 or RAG or prompt」画决策树；估算一个 7B 模型自部署的并发上限。

3. 常见误区 ​

  • ❌ 从数学系教材啃起（目标是 D4 工程，不是发论文）
  • ❌ 追最新论文每个都跑（挑 karpathy 路线与 vLLM 论文两篇精读，其余按需）
  • ❌ mini-vLLM 试图支持所有模型（一个 HF 小模型打穿即可）
  • ❌ 只部署不压测（没有数字的部署在简历上等于零）

4. 面试高频题速答 ​

题速答要点
首 token 为什么慢prefill 算力密集，输入越长越慢；对策：prompt caching、缩短上下文、Chunked Prefill
KV Cache 会不会爆会，显存随 并发×长度 线性涨；对策：分页(PagedAttention)、量化 KV、滑动窗口、prefix 共享
吞吐上不去怎么办静态→连续批处理；调 max_num_seqs / block 数；长请求抢占
什么时候微调格式/风格/领域语感稳定需求；知识更新走 RAG；用成本临界点决策
LoRA 原理冻结基座，旁路低秩 A·B；rank 小、可 merge、QLoRA 让单卡可行
