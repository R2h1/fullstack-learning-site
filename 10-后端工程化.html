10 · 后端工程化 ​

达标目标：L3 硬门槛（工程章节按生产级要求）。 一句话理由：接口写完只是开始——能测、能部署、能守护、能排障，才是"扛住线上"。 对照生产级部署配置（部署脚本 + 服务端目录组织 + 企业级技术栈 Fastify + Prisma + MySQL）。

1. 后端测试体系（L3） ​

1.1 测试分层 ​

单元（handler 纯逻辑/服务函数）→ 集成（真实 DB 起服务）→ e2e（真环境）
  • 单元测试：路由 handler 的纯逻辑、服务函数、工具；不碰 DB/网络
  • 集成测试：起真实服务 + 真实 SQLite，测完整链路（认证 → 校验 → 业务 → 响应）
  • e2e：真环境（生产镜像/预发），关键路径

1.2 测试替身（衔接 04 章，后端版） ​

ts
// 单元测试：隔离外部依赖
import { describe, it, expect, vi } from 'vitest'

// mock 整个 Prisma 客户端
vi.mock('@/lib/prisma', () => ({
  prisma: { book: { findUnique: vi.fn() } },
}))

it('书不存在返回 404', async () => {
  prisma.book.findUnique.mockResolvedValue(null)
  const reply = await getBookHandler({ params: { id: 1 } })
  expect(reply.statusCode).toBe(404)
})

1.3 集成测试：真实 DB + Fastify（L3 必会） ​

ts
import { build } from '@/app'          // 应用工厂（可注入测试配置）
import { prisma } from '@/lib/prisma'

describe('POST /api/books 集成', () => {
  let app
  beforeAll(async () => { app = await build() })
  afterAll(async () => { await app.close(); await prisma.$disconnect() })

  it('校验失败返回 400 统一结构', async () => {
    const res = await app.inject({ method: 'POST', url: '/api/books', payload: {} })
    expect(res.statusCode).toBe(400)
    expect(res.json().error.code).toBe('VALIDATION_ERROR')
  })

  it('正常创建返回 201', async () => {
    const res = await app.inject({ method: 'POST', url: '/api/books', payload: { title: 'x' } })
    expect(res.statusCode).toBe(201)
  })
})
  • app.inject() 是 Fastify 的免端口测试：不发真实网络请求，直接走完整生命周期
  • 覆盖优先：认证中间件、schema 校验失败、错误响应结构、幂等（衔接 09 章）

必会：写集成测试（inject + 真实 DB）；写 mock 替身；说测试分层。

2. 部署（L3） ​

2.1 PM2：进程守护（生产标配） ​

bash
pm2 start dist/index.js --name acme-api          # 启动
pm2 start dist/index.js -i max --name acme-api   # cluster 多进程
pm2 restart acme-api --update-env                # 热更新环境变量
pm2 save && pm2 startup                          # 开机自启
pm2 logs acme-api                                # 看日志
  • --update-env：部署换 .env 后必须带，否则 PM2 用旧环境变量
  • 与 systemd 对比：PM2 上手快 + cluster + 日志轮转；systemd 原生但配置重

2.2 Nginx 反向代理 ​

nginx
server {
  listen 443 ssl;
  server_name api.example.com;
  ssl_certificate     /etc/nginx/ssl/fullchain.pem;
  ssl_certificate_key /etc/nginx/ssl/privkey.pem;

  # 前端静态资源
  location / {
    root /var/www/acme-frontend;
    try_files $uri $uri/ /index.html;        # SPA 回退
    gzip on;                                  # 压缩
  }

  # API 转发
  location /api/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  }
}
  • 每层各防什么（面试爱问）：Nginx 扛连接/静态/SSL/gzip/限流，Node 专注业务，DB 专注数据
  • 常见坑：proxy_pass 结尾斜杠影响路径拼接；未设 X-Forwarded-For 导致拿不到真实 IP（限流/审计会错）

2.3 Docker 多阶段构建（L3 必会） ​

dockerfile
# ---- build 阶段：全量依赖 + 编译 ----
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json pnpm-lock.yaml ./
RUN npm ci                                   # 锁版本安装
COPY . .
RUN npm run build                            # tsc 编译到 dist

# ---- runtime 阶段：只带 dist + prod 依赖，镜像最小 ----
FROM node:20-alpine AS runtime
ENV NODE_ENV=production
WORKDIR /app
COPY --from=build /app/dist ./dist
COPY package.json ./
RUN npm ci --omit=dev && npm cache clean --force   # 只装生产依赖
USER node                                       # 非 root 运行
EXPOSE 3000
CMD ["node", "dist/index.js"]
  • 为什么多阶段：build 阶段装 devDependencies（tsc），runtime 只留 dist + prod 依赖 → 镜像小一个数量级
  • 非 root + .dockerignore（排除 node_modules/dist/.git）
  • 密钥不进镜像：环境变量注入（-e JWT_SECRET 或 secrets）——生产部署在服务器侧写 .env 的做法

必会：写 PM2 常用命令；写 Nginx 静态+API 配置；写多阶段 Dockerfile；讲密钥管理。

3. 可观测三件套（L3） ​

3.1 结构化日志（pino，Fastify 内置） ​

ts
// Fastify 默认 pino：结构化 JSON + 请求级日志
const fastify = Fastify({ logger: true })

// 业务日志带 traceId（衔接 06 章 AsyncLocalStorage）
req.log.info({ userId: req.user?.id, action: 'create_book' }, '创建书')

// 输出示例：一条 JSON
// {"level":30,"time":1700000000000,"msg":"创建书","reqId":"req-1","userId":42,"action":"create_book"}
  • 日志铁律：不打密码/token/密钥；错误日志带堆栈 + 上下文参数；req.log 自带 reqId 贯穿

3.2 指标（Prometheus 思路） ​

指标含义
http_request_total{route}各接口请求量
http_request_duration_ms{quantile}延迟 P50/P95/P99
http_error_total{code}错误率
process_cpu_seconds / process_resident_memory_bytes资源
ts
// 用 onResponse 钩子收集指标（衔接 07 章钩子）
fastify.addHook('onResponse', async (req, reply) => {
  metrics.histogram('http_request_duration_ms', reply.elapsedTime, {
    route: req.routeOptions.url,
    status: String(reply.statusCode),
  })
})
  • 告警阈值示例：P95 延迟 > 1s 持续 5 分钟 → 告警；错误率 > 1% → 告警

3.3 排障链路 ​

告警 → 看指标（哪个接口慢了）→ 看结构化日志（traceId 找这条请求）→ 定位慢查询/依赖
  • traceId 从入口（Nginx 加 X-Request-Id 或应用生成）贯穿到 DB 日志——没有 traceId，多服务排障是灾难

必会：写结构化日志（req.log + traceId）；讲指标四件套与告警阈值；画排障链路。

4. 优雅关闭与进程兜底（L3） ​

4.1 完整优雅关闭（衔接 06 章，这里讲 Fastify 版） ​

ts
const server = await fastify.listen({ port: 3000 })

async function shutdown(signal) {
  fastify.log.info({ signal }, '优雅关闭')
  await fastify.close()            // 停新请求，等存量完成，触发 onClose
  await prisma.$disconnect()       // 释放连接池
  process.exit(0)
}
process.on('SIGTERM', shutdown)
process.on('SIGINT', shutdown)

// 兜底：超时强杀 + 未处理拒绝
setTimeout(() => process.exit(1), 30_000).unref()
process.on('unhandledRejection', (r) => { console.error('未处理拒绝', r); process.exit(1) })
  • 生产版 index.ts 即此模式（close → disconnect → exit + 信号监听）

4.2 进程兜底策略 ​

  • uncaughtException/unhandledRejection → 记录 + 退出，交给 PM2/Docker restart 重启（衔接 06 章）
  • PM2 restart 策略、Docker restart: unless-stopped

必会：默写 Fastify 优雅关闭；讲进程兜底"记录+退出+守护重启"。

5. 后端 CI/CD（L3） ​

yaml
# 后端 CI：lint → 类型 → 单测 → 集成 → 构建
name: Backend CI
on:
  push:
    paths: ['packages/server/**', 'pnpm-lock.yaml']
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }   # pnpm 11 要求 Node ≥ 22.13
      - run: npm i -g pnpm@11
      - uses: actions/cache@v4
        with:
          path: ~/.local/share/pnpm/store
          key: pnpm-${{ hashFiles('pnpm-lock.yaml') }}
      - run: pnpm install --frozen-lockfile
      - run: pnpm --filter server lint
      - run: pnpm --filter server build        # 类型检查 + 编译
      - run: pnpm --filter server test          # 单元 + 集成
  • 数据库迁移与部署解耦：CI 只测代码；prisma db push 在部署步骤（服务器上）执行，保留线上数据（生产部署的做法）
  • 部署三件套顺序：构建 → 同步文件（rsync/镜像）→ 服务器上 db push + 重启 PM2

必会：写后端 CI yaml；讲"迁移与部署解耦"为什么重要。

6. 面试高频题速答 ​

题速答要点
后端测试怎么分层单元 → 集成（真 DB + inject）→ e2e；替身隔离外部
Fastify inject 是什么免端口测试，走完整生命周期
PM2 怎么守护cluster + --update-env + save/startup；崩溃自动重启
Nginx 每层防什么静态/连接/SSL/gzip/真实IP，Node 专注业务
Docker 多阶段干嘛build 全量编译、runtime 最小镜像 + 非 root
密钥为什么不进镜像环境变量/Secrets，泄漏即灾难
日志带什么结构化 JSON + traceId + reqId，不打敏感信息
排障链路告警 → 指标 → traceId 日志 → 慢查询
迁移为什么和部署解耦代码可回滚，数据迁移不可随意回滚
