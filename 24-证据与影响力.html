24 · 证据与影响力（操练册） ​

达标目标：把 D4 的产出变成市场看得见、搜得到、能被引用的 D5 证据：至少 1 个被 merge 的主流项目 PR、10 篇深度技术文、一份每条都能被追问三层的简历。 一句话理由：到 D4 你已经有实力，但简历只负责传递信号——没有义务隔着 200 份材料摸到你的实力；D5 是把证据提前放在他们看得见的地方。 衔接：20 章（验收物 8/9/10）、21/22/23 章（全部素材的来源库）、18 章（面试表达框架）。 ⚠️ 操练册：本章所有条目都以「链接存在」为完成标志，没有链接等于没做。

1. D5 证据的构成与顺序 ​

证据作用成本优先级
被 merge 的 PR你的代码被同行评审过——最强背书中★★★
有质量的引擎仓库21/22 章产物自然沉淀，star 是锦上添花低（已写完）★★★
深度技术文 ×10思考外化；面试官与内推人会搜中★★★
简历以上所有证据的目录页低★★★

顺序有讲究：仓库随写随沉，文章随手就发，PR 放在阶段三集中投，简历投递前重写三版。 反过来做（先改简历再补证据）必然空转。

2. 开源贡献 Playbook（目标：阶段三内 ≥1 个非 docs merge） ​

  1. 选靶子：你真实用过、issue 流动快的中型以上项目——LangGraph / vLLM / Langfuse / Eino / BullMQ 这一档。不选内核级巨兽（反馈周期太长），不选 5-star 玩具（评审不了你）。
  2. 入场路径（由易到难）：docs 失效链接 → 先写最小复现再认领未闭环 bug → 测试补齐 → 小特性/小性能。docs PR 用来练流程，不算终点；目标是 1 个非 docs merge。
  3. 读源码的正确姿势：不要从 utils 第一行通读。从你项目里一次真实调用出发（RAG 的一次检索进 LangGraph 走了哪条边？vLLM 的调度循环在哪 sleep？），顺着打断点、画时序图——读到的永远是「你问题的答案」，不是「别人的架构」。
  4. PR 素养：读 CONTRIBUTING；先提 issue 占坑；一个 PR 只解决一件事；测试与 changelog 按项目规矩来；被要求改 10 轮是常态——韧性本身就是信号，reviewer 会记住。
  5. 讲法：面试里讲「我定位了什么、复现了什么、review 教会我什么」，永远不要报 star 数。

必会：白板画出「使用 → 追调用读源码 → 最小复现 → issue → PR merge」全路径，每步给时间盒（源码 2 周 / 复现 3 天 / PR 2 周）。

3. 深度写作：10 篇的排期与文体 ​

选题公式：真实踩坑 + 数据对比 + 可运行仓库，三者缺一不发。 只有第一手素材才写，追热点翻译文对 D5 零贡献。

篇次文体素材来源发布时机
1–4踩坑复盘（故障/badcase）23 章「故障日」与红队报告阶段一/二随时
5–7引擎复现报告（mini-vLLM/Raft/LSM 设计取舍）21/22 章仓库 README 扩写引擎收口时
8–9评测文（RAG 评估全链路 / 某开源组件评测）23 章评估报告阶段三前
10转型叙事（4 年前端 → 全栈+AI 完整复盘）20 章月度 journal 汇总投递前 1 个月
  • 阵地：掘金/知乎 + GitHub Pages（本站）同步发；每篇挂一个可运行仓库链接
  • 标题规则：具体名词 + 数字（「我写了个 mini-vLLM，吞吐追平官方 40% 的过程」），不写「详解/从入门到精通」
  • 硬指标：≥1 篇被同行转发或被 issue 引用；全部篇目在简历里有链接

4. 简历重写：证据的目录页 ​

规则：每条 bullet = 动作 + 方法 + 数字，能被追问三层才配写上。 写不出第三问，就还没到能写的程度。

反例（能力宣称）改写（证据引用）
熟悉 Redis，了解缓存SaaS 后端落地缓存+队列链路，P99 800ms → 120ms；自研 LSM/MQ 后能讲清 Redis/Kafka 的设计边界
做过 RAG 系统生产级 RAG：150 条 golden set，Recall@5 0.61 → 0.84；Faithfulness 走 LLM-as-Judge + 人工抽检校准；语义缓存降本 31%
学习能力强24 个月：3 个引擎级仓库全带测试，vLLM 被 merge PR ×1，深度技术文 10 篇（链接）

节奏：投递前重写出 3 版，每版投 5–10 家，用「约面率/追问深度」迭代。约面率 <20% 说明证据没传递出去（标题、阵地、推荐人），不是能力问题——别改能力，改分发。

5. 模拟面试配额（阶段三固定动作） ​

类型次数复盘要点
算法限时（25 min/题）10卡壳题型回 20 章算法轨道补
系统设计白板5前 30 秒给高层数据流，之后按追问深入；数字张口就来
项目深挖（30 min 连续追问）5每轮至少被追到第 4 层不崩（素材全部来自仓库与复盘文档）
行为面3转型动机/冲突/带教故事，从 journal 取材，不即兴

真人 2–3 位（前同事/社区），全程录屏复盘；AI mock 只当热身，不当达标依据。

6. 市场验证：让目标替你打分 ​

  • JD 对照：拉目标公司近 3 个月 JD，高频技术词逐个映射到 20 章验收物表；映射不上的就是新缺口，开小坑补而不是背话术
  • 职级信号：能直达二/三面（内推生效）、拿到 2–3 家同档 offer、对方愿意为「作品链接」加快流程——三者任一出现，证据链生效
  • 反脆弱：每半年滚动更新一次证据（新 PR / 新文 / 项目新数字），让简历持续增值而不是保鲜

7. 达标标准（对照 20 章验收物 8/9/10） ​

D5：

  • [ ] ≥1 个非 docs PR 被主流项目 merge（链接入简历）
  • [ ] 10 篇全部发布，≥1 篇被同行转发或被 issue 引用
  • [ ] 简历 3 版，最终版约面率 ≥40%
  • [ ] 模拟面试配额（10/5/5/3）完成且有录屏复盘

毕业判定：20 章第 1 节验收物表 10 项全绿。此时问题不再是「能不能过面试」，而是「选哪家」。
