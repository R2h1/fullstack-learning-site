22 · 长矛二：分布式内核（操练册） ​

达标目标：造出分布式的三块基石并测对：Raft 共识、LSM 存储引擎、带重试与死信的消息队列。 一句话理由：12 章教你「用」Redis/MQ/副本集，大厂后端定级的分水岭在于你是否造过它们——Raft 写对的那一刻，CAP、一致性、选主不再是话术，是伤疤。 衔接：11 章（B+ 树与事务——LSM 是它的对位答案）、12 章（缓存/CAP/MQ 的概念层）、13 章（系统设计——本章给它装上引擎盖）。 ⚠️ 操练册：每块引擎以「正确性测试通过」为唯一完成标准，写完没测 = 没写。

1. 为什么选这三块 ​

  • Raft：一切高可用中间件的底座（etcd、Kafka KRaft、TiKV 都实现了它）。面试问「副本怎么保证一致性」，能推导 Raft 的人直接结束战斗
  • LSM-tree：写优化存储的另一极（RocksDB 家族），对位 11 章 B+ 树；理解了 compaction，就理解了「写放大/读放大/空间放大」这个工程世界的三角权衡
  • MQ：12 章里最薄的部分（站点 Kafka/RabbitMQ 零覆盖），而它是 AI 工程化的刚需（批处理、背压都靠它，对位 23 章）

三块共享一个内核：日志 + 状态机。造完你会发现 Raft 的 log、LSM 的 WAL、MQ 的 partition log 是同构的——这是本章最值钱的一句话。

2. 路线（约 14–18 周，与 21 章并行则各半速） ​

2.1 Raft（第 1–6 周） ​

  • 交付物：miniraft——单语言打穿（Go/Python/TS 任选）：leader election（随机超时）、log replication、commit、apply；持久化 + 快照先不做，最后补
  • 测试标准（唯一裁判）：
    1. 单元测试：election timeout 区间内选主成功、网络分区恢复后旧 leader 退位（term 单调）
    2. 场景测试：杀 leader → 重选耗时上界；脑测分区 → 无 commit 丢失；参照 tests-in-etcd 的思路自搭双集群对比测试
  • 必读：Raft 论文 + Raft 可视化；写之前先把状态图自己画一遍再对照
  • 坑预告：votedFor 的时机、commitIndex 推进规则「只能提交当前 term 的日志」、preVote（不做会踩选举风暴，作为进阶）

必会：白板推导一次选主 + 三条日志复制；讲清「为什么多数派」与节点数/副本数关系。

2.2 LSM 存储引擎（第 7–11 周） ​

  • 交付物：minilsm——memtable(跳表) → WAL → flush 成 SSTable → leveled compaction → 点查/范围查（Bloom filter + block index 加速）；API 只要 put/get/delete/scan
  • 测试标准：kill -9 后恢复无数据丢失（WAL 回放）；compaction 前后读写结果一致；基准 vs 裸 B 树（11 章 MySQL 的表世界）——写出写放大数字
  • 与 11 章闭环：用自己的 LSM 和 InnoDB 各跑一次写密集基准，解释为什么「写多读少」选了不同的树

2.3 消息队列（第 12–15 周） ​

  • 交付物：minimq——单分区起步：append-only log（复用 2.2 的存储件！）+ producer offset 管理 + consumer pull + at-least-once 语义；再加分区与重平衡；最后补延迟重试队列 + 死信（对齐路线图阶段一的「重试与死信」）
  • 测试标准：生产者崩溃重发后消费者幂等验证（对位 09 章）；kill broker 恢复后不丢已 ack 消息
  • 必会：at-most/at-least/exactly-once 的实现代价；ISR vs Raft 多数派——Kafka 与 etcd 治同一种病的两套药，为什么

本章 D4 终点：三件全带测试通过 + 每件一篇设计 README（取舍记录，面试直接用）。

3. 常见误区 ​

  • ❌ 一上来做多语言/分布式部署版 Raft（先单机模拟消息传递，正确性 > 真实性）
  • ❌ 跳过测试用「看起来能跑」交差（Raft 不测分区行为等于没写）
  • ❌ LSM 上 Bloom filter 调参花两周（先用朴素实现过基准，再优化）
  • ❌ MQ 做 exactly-once（工业界靠幂等 + at-least-once，学事务消息概念即可）

4. 达标标准 ​

L2：

  • [ ] 讲清 Raft 选主/复制/安全三规则；画 LSM 读写路径与 compaction 策略
  • [ ] 答「Kafka 为什么不选 Raft 用 ISR」并说各自代价

L3：

  • [ ] minimq 在项目一（SaaS 后端）里真接一条业务链路（如异步发通知），带监控

D4：

  • [ ] 三仓库测试绿 + 基准报告 + 设计 README，至少一件被他人 review
