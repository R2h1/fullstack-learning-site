01
后端全栈 10–12 周
目标：具备独立设计、实现并部署一个后端服务的完整能力
0/9
▼
Node.js NestJS PostgreSQL Prisma Redis Docker / CI/CD
核心任务
面试锚点（要能讲出来）
  • 为什么选 NestJS 而非 Express？DI 与模块化对团队协作的长期收益
  • 你的表怎么设计、索引为什么加在这里
  • 事务边界怎么划、并发下如何保证一致性
  • JWT 刷新怎么做、token 泄漏怎么兜底
  • 代码从提交到生产经过哪些环节
前端补强（并行）
  • JS 底层：闭包与内存泄漏、Promise/A+、并发调度器
  • 浏览器：CRP 渲染链路、重排/重绘、V8 分代回收
  • 性能：Performance 面板定位瓶颈、堆快照排查
阶段产出：一个 SaaS 后端 API 项目 —— 认证 + 数据库 CRUD + 缓存 + Docker 部署。
这是你第一个可面试项目，重点准备「架构取舍 + 一个你排查过的生产问题」。
⚠️ 选择 Java 路线时：本阶段仍然先学 NestJS（建立后端架构思维），完成后再追加 2–3 个月 Java 分支（见下方红色卡片）。数据库可改用 MySQL。

关键认知
  • NestJS 的 DI、模块化、装饰器与 Spring 高度相似，架构思维可无损迁移
  • 真正的门槛是Java 语言本身与 JVM 生态，不是后端概念
  • 合理目标是「能写业务 + 能维护」，精通 Spring 生态不是当前任务
02
AI 应用工程 8–10 周
目标：以「AI 应用工程师」定位，构建可评估、可监控、可部署的 RAG 系统
0/10
▼
Python / FastAPI LangChain LangGraph pgvector Langfuse Next.js
核心任务
面试锚点（要能讲出来）
  • 完整讲一遍 RAG 全链路，每一步的取舍
  • 检索质量差怎么优化（检索 → 生成 → 评估三层展开）
  • 幻觉怎么兜底、怎么衡量
  • 延迟和成本怎么控制（缓存 / 模型分级 / 流式）
  • 一个真实的 badcase 排障过程
前端补强：AI 原生前端
  • 手写 SSE 流式解析 + AbortController 中断
  • 残缺 JSON 增量解析与容错渲染
  • Agent 多工具调用的异步状态机
  • 生成内容沙盒隔离与降级策略
  • Sentry 打通前端 → 后端 → DB 分布式追踪
阶段产出：一个生产级 RAG 系统 + AI 前端（流式对话、引用展示）。
前端 4 年经验的优势在这里直接兑现：流式 UI、对话状态管理、交互体验设计。

后端先行，不是拖延

AI 应用的质量高度依赖后端工程能力。跳过后端直接做 AI，会在「服务怎么部署、并发怎么扛」上暴露短板。

每个阶段必须有一个项目

读书笔记不会让你通过面试，可运行、可展示、可复盘的项目才会。两个项目就是两个锚点。

前端补强不单独开线

嵌入每个阶段作为质量门槛：阶段一补底层与性能，阶段二补 AI 原生前端，阶段三补可观测性。

数据库优先级最高

这是前端转后端思维转变最困难、面试权重却最高的一环。SQL 与 PostgreSQL 必须集中攻克。
