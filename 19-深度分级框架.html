19 · 深度分级框架：D1–D5 ​

达标目标：能用 D1–D5 给自己任何一项技术能力定坐标，并说出下一级要交付什么。 一句话理由：「学完了」不是状态，「造出来了」才是。分级从「会讲」升级为「造得出、改得动」，是为了回答一个更硬的问题——离地表最强还差哪几件东西。 衔接：20 章（计划、里程碑与验收物）；15/16 章（AI 应用层的既有内容）；11/13 章（后端与系统设计的既有内容）。

1. L 与 D：两张梯子各管一件事 ​

原来的 L1/L2/L3 继续有效，但它只回答「讲到什么程度」。新加一把纵向的 D 梯，回答「长到哪个楼层」。会讲八股（L2）和造得出引擎（D4）是两回事，很多人误把 L3 当终点。

级别问题判据
L1 会用会不会用照教程做出 demo
L2 面试级会不会讲不看资料答出「必会」/速答表
L3 生产级有没有做过真实项目里做对过工程决策
D1 地基知识地图知道这层有什么、坑在哪
D2 讲得清原理叙述八股与高频题（= L2）
D3 生产级工程决策做过 + 有数字（= L3）
D4 造得出引擎复现从零造出该领域核心机制，带正确性测试
D5 改得动开源与影响读得懂主流源码、PR 被 merge、有被转发的深度输出

「地表最强」的可操作定义：一个 D3 宽环 + 至少两把 D4 长矛 + 一条证据链收口到 D5。

2. D 梯判据细则（自评用，别自欺） ​

D2 讲得清 ​

  • 能白板画出该领域的全链路并讲取舍，接受三层追问不卡壳
  • 现状：01–18 章的目标层，绝大多数人停在这里

D3 生产级 ​

  • 真实项目做过工程决策，能给出 QPS、P99、成本、故障 MTTR 中的至少三个数字
  • 复盘过一次线上故障：现象 → 定位 → 修复 → 防复发
  • 现状：路线图阶段一/二的验收层；18 章里只有模板，没有载体

D4 造得出 ​

  • 该领域的核心引擎自己实现过一遍，配正确性测试，不是库 API 的调用组合
  • 例：mini-vLLM 调度器、Raft 集群、LSM 存储引擎、带评估挂 CI 的 RAG 管道
  • 与 D3 的区别：D3 是「用过并调好」，D4 是「造过并测对」

D5 改得动 ​

  • 给主流开源项目（LangGraph / vLLM / Eino 之类）提过被 merge 的 PR
  • 写过至少一篇让同行转发的深度复现或评测
  • 与 D4 的区别：D4 证明你能造，D5 证明别人拿你的东西当参考

3. 站点三层结构 ​

层内容定位维护规则
教材环01–18 章通用企业级教材，D1–D3守既有写作约定，保持通用定位
长矛区19 章起操练册：任务、验收物、产出物可按阶段迭代，不受教材标准约束
证据链项目仓库、评估报告、输出物简历与面试的弹药库每阶段收口一次，产出物计数为准

教材环每章末尾新增 「深潜入口」D4 框：一句话指认该领域造一遍核心是什么、对应长矛区哪条路。先补 15 章（AI → 20 章）和 11 章（存储 → 21 章）。

4. 为什么不能平均用力 ​

广度和深度都想要的人，最常见的下场是「什么都懂一点」——那是平庸的最高配置。强者的形状是 π 型：

  • 宽环：处处到 D3，保证接得住任何方向的问题
  • 长矛：2–3 个领域捅到 D4，保证追问第五层还有东西可讲
  • 证据链：把前两者变成别人否认不了的东西（仓库、报告、PR、文章）

长矛必须早选，因为引擎级能力靠累计小时堆，晚选一个月就少一个月。默认两把：AI 推理层（20 章）与分布式内核（21 章），二者互喂——RAG 系统本身就是分布式系统。

6. 面试高频题速答 ​

题速答要点
你怎么定义自己的技术深度用 D 梯报坐标：哪个领域到 D4、验收物是什么
八股和项目哪个重要八股到 D2 是门票，定级看 D3 数字与 D4 作品
怎么快速评估一个新领域画 D 梯 → 找该领域「造一遍核心」的最小路径
