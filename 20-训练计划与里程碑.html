20 · 训练计划：24 个月与验收物 ​

达标目标：按本计划执行到第 24 个月，凑齐「地表最强」的验收物清单；每月末用本章的复盘模板交作业给自己。 一句话理由：教材读得再熟，验收物为零就是零。计划的作用不是排课表，是把「学完」换成「交付了什么」。 衔接：19 章（D1–D5 分级）；21–24 章（长矛与证据）。

1. 总目标与验收物计数 ​

终点不是「学完」，是下面这张表填满：

#验收物D 层判据
1算法：力扣 200+，medium 20 分钟 AC 率 >70%门票周统计截图，AC 时间分布
2项目一：高并发 SaaS 后端，真实 50–500 用户D3QPS / P99 / 单位成本 三组数字 + 一次故障复盘
3项目二：生产级 RAG，带评估报告D4Recall@k、Faithfulness 曲线、优化前后对比、token 账单
4引擎仓库一：mini-vLLM 调度器（continuous batching）D4带吞吐压测报告，TTFT/TPOT 对比
5引擎仓库二：Raft 集群实现D4通过正确性测试（网络分区/节点宕机场景）
6引擎仓库三：LSM 存储引擎 + 简易 MQD4各自的正确性测试与基准
7微调实证：LoRA 微调一个小模型解决一个真实分类任务D4训练配置、eval 指标、成本
8开源：主流 AI/后端项目被 merge 的 PR ≥1D5PR 链接 + review 过程
9输出：深度技术文 ≥10 篇，其中 1 篇被同行转发D5链接与阅读/转发数据
10简历：用项目锚点 + 数字重写—每条 bullet 能被追问三层

计数规则：一项没有对应仓库/报告/链接，就不算完成。「看完了」不进入这张表。

2. 每日与每周轨道 ​

时间预算沿用路线图的 12–15 h/周，切成三条并行轨道，任何阶段都不停：

轨道频率单次时长内容
🗡️ 长矛每周 4 次90–120 min引擎实现，必须产出 commit
📖 教材每周 3 次60–90 min01–18 章，读完当场写 1 条「我怎么验证它」
🧮 算法每天30–45 min1 新题 + 1 复习，周日晚统计 AC 率

长矛与教材的比例在阶段二调整为 6:2，阶段三（面试冲刺）调整为 3:3:2 加模拟面试。

3. 三阶段排期 ​

阶段一（第 1–9 个月）：宽环到 D3 + 门票打磨 ​

  • 教材：01–18 全过一遍到 L2，其中 08/09/11/12/13/15/16 到 L3
  • 项目一（SaaS 后端）全程并行：第 2 月上线、第 4 月引入真实用户、第 6 月制造并复盘一次容量故障
  • 算法：100 题起步，建立题型地图（22 章的算法部分或外部题单）
  • 里程碑验收：项目一有公网地址 + 三组数字；算法 100 题；教材 L2 全绿

阶段二（第 10–18 个月）：两把长矛到 D4 ​

  • 长矛一（21 章 AI 推理层）：nanoGPT 路线 → LoRA 微调 → vLLM 使用与压测 → mini-vLLM
  • 长矛二（22 章 分布式内核）：Raft → LSM → 简易 MQ
  • 项目二（生产级 RAG，23 章评估体系）作为两把长矛的交汇点：既是分布式系统，又需要推理与评估判断
  • 里程碑验收：验收物 3/4/5/6/7 全部有仓库和报告

阶段三（第 19–24 个月）：证据收口 + 市场验证 ​

  • 24 章：开源 PR、深度写作、简历重写、模拟面试（系统设计 + 项目深挖各 5 轮）
  • 项目一/二持续运营，把数字做厚（留存、营收或成本下降的任意一个真实指标）
  • 真实投递：以「拿头部 offer」为验证，不以「过面」为目标
  • 里程碑验收：验收物 8/9/10

4. 选型口径（消除站点与路线图的矛盾） ​

教材主线用 Fastify + Prisma + MySQL（通用企业级定位，01–18 章不动）。

两个旗舰项目与长矛统一用：

层选型理由
后端框架NestJS（TS）DI/模块化对标 Spring，讲「架构取舍」最有料；14 章的迁移逻辑成立
数据库PostgreSQL + pgvectorAI 项目向量与业务数据同库，省一层基础设施
ORMPrisma教材已覆盖，迁移零成本
AI 服务Python + FastAPI模型生态只在 Python 侧；mini-vLLM 也用它写
推理vLLM（使用与压测）→ 自建 mini-vLLM（学习）会用与懂原理分层取证
评估RAGAS + Langfuse一个给指标，一个给 trace

对照表（14/07 章的概念可直接映射）：Fastify 钩子 ↔ NestJS 拦截器/管道；Express ↔ Spring MVC；Prisma 迁移 ↔ Flyway。

5. 每月复盘模板 ​

每月最后一天，30 分钟填完，存进项目仓库的 journal/ 目录（同时也是 D5 输出的素材）：

md
## YYYY-MM 复盘

- 长矛进度：本周 commit N 次，卡在 ___（具体到函数/测试名）
- 验收物增量：新增 ___（链接），仍缺 ___
- 教材回填：本月把 ___ 章的一处说法改掉了，因为实践中 ___
- 数字：算法 AC 率 __%；项目真实用户 __；token 成本 __
- 下月唯一重点：___

「教材回填」是硬要求：实践中发现站点讲得不准，就回去改章节。这也是站点从「教材」变成「活文档」的方式。

6. 风险与止损 ​

风险症状处置
只刷教材不做连续两周无 commit长矛优先砍到每天 30 min，也要保住动手
引擎烂尾有 repo 无测试停止开新坑，先用测试收口上一个
项目无用户数字全是压测阶段一结束前必须公开上线，哪怕只有 20 个真实用户
时间崩盘三轨道全断保留算法 + 长矛，教材暂停（教材可以面试前突击）

7. 达标标准 ​

执行：

  • [ ] 三轨道连续 4 周无中断，有 commit 与 journal 记录
  • [ ] 阶段一末：验收物 1、2 达成
  • [ ] 阶段二末：验收物 3–7 达成
  • [ ] 阶段三末：验收物 8–10 达成
